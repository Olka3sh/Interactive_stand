## 3. Замечания к коду коллеги

*(Замечания оформлены в Issues репозитория `dome-planetarium` с меткой `code-review`)*

### 1. Отсутствие проверки входного списка инцидентов на `null` в `analyzeSessionTelemetry`
- **Ссылка на Issue:** https://github.com/Andruschka77/dome-planetarium/issues/1
- **Файл и место:** `java/src/model/ShowSession.java`, метод `analyzeSessionTelemetry(List incidents)` (строки 93–124).
- **В чём проблема:** В методе не проверяется переданный список инцидентов `incidents` на `null`. Если вызывающий код передаст `incidents == null`, при первом же обращении в цикле `for (TelemetryIncident inc : incidents)` возникнет необработанное исключение `NullPointerException`.
- **Предложение по исправлению:** Добавить в начало метода защитную проверку инициализации пустым списком:
  ```java
  if (incidents == null) {
      incidents = Collections.emptyList();
  }
  ```

### 2. Отсутствие fallback-стратегии и проверки на `null` для `CalibrationRule`
- **Ссылка на Issue:** https://github.com/Andruschka77/dome-planetarium/issues/2
- **Файл и место:** `java/src/model/CalibrationProfile.java`, метод `verifyClusterCalibration` (строки 96–122).
- **В чём проблема:** Переданный параметр стратегии сшивки `CalibrationRule rule` не проверяется на `null`. Если вызывающий код передаст `rule == null`, вызов метода `rule.calculateBlendWidth(rmsError, toleranceThreshold)` аварийно завершится с `NullPointerException`.
- **Предложение по исправлению:** Добавить в начало метода безопасную подстановку стандартной реализации по умолчанию:
  ```java
  if (rule == null) {
      rule = new StandardBlendRuleImpl();
  }
  ```

### 3. Использование магического числа для температурного порога лазера в `checkProjectorsReadiness`
- **Ссылка на Issue:** https://github.com/Andruschka77/dome-planetarium/issues/3
- **Файл и место:** `java/src/model/Projector.java`, метод `checkProjectorsReadiness(List projectors)` (строки 56–60).
- **В чём проблема:** Пороговое значение температуры лазерного блока 70 градусов захардкожено непосредственно внутри условного оператора (`p.getLaserTempCelsius() >= 70`). Использование неименованных литералов («магических чисел») ухудшает читаемость кода и усложняет его дальнейшую модификацию.
- **Предложение по исправлению:** Объявить в классе статическую константу:
  ```java
  public static final double MAX_LASER_TEMP_CELSIUS = 70.0;
  ```
  и использовать её в условии проверки аппаратного статуса проектора.
