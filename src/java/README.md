# Объектно-ориентированная реализация ядра системы (Контрольная точка №3)

---

## 1. Стек технологий и среда выполнения

- **Язык программирования:** Java 21 (LTS, дистрибутив Eclipse Temurin / OpenJDK 21)
- **Инструмент сборки:** стандартный компилятор `javac` из состава JDK 21 (сторонние зависимости и внешние библиотеки не используются)
- **Парадигма:** Объектно-ориентированное программирование (ООП) с соблюдением принципов SOLID и шаблона проектирования «Стратегия» (Strategy)
- **Используемые библиотеки:**
  - Стандартная библиотека Java (`java.time.LocalDate`, `java.util.List`, `java.util.ArrayList`, `java.util.Map`, `java.util.HashMap`, `java.util.LinkedHashMap`, `java.util.Collections`, `java.util.Objects`, `java.util.Locale`).
  - Хранение данных осуществляется в оперативной памяти без подключения внешней СУБД (подключение PostgreSQL выполняется на следующем этапе КТ4).

## 2. Архитектура решения и структура файлов

Кодовая база состоит из **13 классов и интерфейсов**, расположенных в каталоге `src/java/`:

```text
src/java/
├── Customer.java                 # Заказчик выставочного оборудования (регистрация заказа)
├── Order.java                    # Производственный заказ (проверка дефицита и расчёт себестоимости)
├── OrderComponent.java           # Ассоциативная сущность позиции спецификации заказа (M:N)
├── Component.java                # Номенклатурная единица комплектующего на складе
├── Employee.java                 # Сотрудник предприятия (конструктор, инженер, специалист ОТК)
├── Operation.java                # Технологическая операция производственного цикла
├── Defect.java                   # Абстрактный базовый класс дефекта приёмочных испытаний («abstract»)
├── HardwareDefect.java           # Аппаратно-конструктивный дефект (наследник Defect)
├── SoftwareDefect.java           # Программный дефект (наследник Defect)
├── CostCalculationStrategy.java  # Интерфейс стратегии расчёта стоимости позиции («interface»)
├── StandardCostStrategy.java     # Стандартная стратегия расчёта стоимости по прайс-листу
├── DiscountCostStrategy.java     # Оптовая стратегия расчёта стоимости со скидкой
├── Main.java                     # Точка входа: инициализация данных и запуск всех операций
└── README.md                     # Руководство по ООП-модулю (КТ3)
```

## 3. Реализация принципов ООП

1. **Инкапсуляция:**
   - Все поля сущностей объявлены с модификатором доступа `private` (идентификаторы и неизменяемые связи помечены `final`).
   - Доступ к состоянию объектов осуществляется через геттеры и предметные методы с валидацией входных параметров (`IllegalArgumentException`, `Objects.requireNonNull`).
   - Внутренние коллекции защищены от внешней модификации возвратом неизменяемых представлений через `Collections.unmodifiableList(...)` в `Order.getItems()` и `Operation.getDefects()`.
2. **Наследование:**
   - Абстрактный класс `Defect` является общим предком для конкретных видов брака: `HardwareDefect` и `SoftwareDefect`.
   - Общие атрибуты (`idDefect`, `description`, `severity`, `foundDate`, `fixedDate`, `status`, `employee`, `operation`) и геттеры вынесены в суперкласс.
3. **Полиморфизм:**
   - Методы `getDefectCategory()` и `getRoutingTarget()` объявлены абстрактными в `Defect` и переопределены в подклассах `HardwareDefect` (маршрутизация сборщику на переборку) и `SoftwareDefect` (маршрутизация программисту на отладку ПО). Подсчёт статистики в `Operation.analyzeDefectStatistics(...)` выполняется полиморфно при обходе списка `List<Defect>`.
   - Правила расчёта стоимости позиций (`StandardCostStrategy` и `DiscountCostStrategy`) взаимозаменяемы через общий интерфейс `CostCalculationStrategy`.
4. **Абстракция:**
   - Выделены ключевые сущности предметной области производства интерактивных стендов в полном соответствии с логической моделью данных (7 сущностей: `Customer`, `Order`, `OrderComponent`, `Component`, `Employee`, `Operation`, `Defect`).
5. **Паттерн «Стратегия» (Strategy):**
   - Метод `Order.checkMaterialsDeficit(stockMap, strategy)` делегирует вычисление стоимости каждой позиции переданному объекту `CostCalculationStrategy`, что позволяет добавлять новые тарифные правила (например, оптовую скидку) без изменения кода классов `Order` и `OrderComponent` (принцип Open-Closed).

## 5. Реализованные операции и алгоритмы

1. **Операция 1: `Customer.registerProductionOrder(orders, description, createdDate, plannedDays)`**
   - Автоматическая регистрация нового производственного заказа с генерацией следующего `idOrder`, фиксацией даты создания, расчётом плановой даты завершения (`createdDate + plannedDays`), присвоением статуса `«Зарегистрирован»` и привязкой к объекту заказчика `this`.
2. **Алгоритм 1: `Order.checkMaterialsDeficit(stockMap, strategy)`**
   - Проверка достаточности текущих складских остатков `stockMap` для всех позиций спецификации заказа (`OrderComponent`).
   - При нехватке комплектующих фиксируется запись дефицита (`id_order`, `id_component`, `deficit`); при достаточности — выполняется виртуальное списание остатка со склада и расчёт плановой себестоимости заказа через выбранную стратегию `CostCalculationStrategy`.
3. **Алгоритм 2: `Operation.analyzeDefectStatistics(totalInspections)`**
   - Однопроходная агрегация журнала рекламаций ОТК (`List<Defect>`), вычисление общего процента брака (`defect_rate`), подсчёт количества и структурных долей аппаратных (`hw_count`, `hw_ratio`) и программных (`sw_count`, `sw_ratio`) дефектов.
