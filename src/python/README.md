## 1. Стек технологий и среда выполнения

- **Язык программирования:** Python 3.13 (тестировалось на версии 3.13.7)
- **Инструмент запуска:** стандартный интерпретатор `python` (установка сторонних пакетов не требуется)
- **Парадигма:** Процедурное программирование без использования пользовательских классов
- **Используемые библиотеки и структуры данных:**
  - Стандартная библиотека Python (`datetime.date`, `datetime.timedelta`).
  - Моделирование сущностей предметной области выполнено с помощью встроенных структур данных: словарей (`dict`) и списков (`list`).
  - Хранение данных осуществляется в оперативной памяти без подключения внешней СУБД.

## 3. Особенности процедурной реализации

1. **Отсутствие пользовательских классов:**
   - Все сущности логической модели (`customers`, `components`, `orders`, `order_components`, `defects`) представлены в виде стандартных словарей `dict` и списков `list`.
2. **Разделение данных и логики:**
   - Состояние системы передаётся в виде аргументов между независимыми функциями обработки (`register_production_order`, `check_materials_deficit`, `analyze_defect_statistics`).
3. **Изоляция побочных эффектов:**
   - В функции `check_materials_deficit` перед проверкой спецификаций формируется локальная копия складских остатков `stock_map`, что предотвращает порчу исходного справочника `components` при расчёте партии заказов.
4. **Защита от некорректных данных:**
   - В `register_production_order` проверяется существование заказчика `id_customer` в словаре `customers` с выбросом `ValueError`.
   - В `analyze_defect_statistics` обрабатывается граничный случай `total_inspections <= 0` и `total_defects == 0` без деления на ноль.

## 5. Реализованные операции и алгоритмы

1. **Операция 1: `register_production_order(orders, customers, id_customer, description, created_date=None, planned_days=14)`**
   - Автоматическая регистрация нового производственного заказа с вычислением следующего `id_order`, расчётом плановой даты завершения (`start_date + timedelta(days=planned_days)`), присвоением статуса `«Зарегистрирован»` и добавлением записи в список `orders`.
2. **Алгоритм 1: `check_materials_deficit(orders, order_components, components)`**
   - Проверка обеспеченности позиций спецификаций партии заказов текущими складскими остатками с использованием вложенных циклов `while`.
   - При нехватке комплектующих формирует запись в списке `deficit_list`; при достаточности — списывает остаток из `stock_map` и суммирует плановую себестоимость `total_cost`.
   - **Вычислительная сложность:** по времени — $O(C + N \cdot M)$, по памяти — $O(C + N \cdot M)$, где $N$ — число заказов, $M$ — максимальное число позиций в заказе, $C$ — количество номенклатурных позиций на складе.
3. **Алгоритм 2: `analyze_defect_statistics(defects, total_inspections)`**
   - Однопроходная линейная агрегация журнала рекламаций ОТК (`while k < len(defects)`), вычисление общего процента брака (`defect_rate`), подсчёт количества и структурных долей аппаратных (`hw_count`, `hw_ratio`) и программных (`sw_count`, `sw_ratio`) дефектов.
   - **Вычислительная сложность:** по времени — $O(K)$, по памяти — $O(1)$, где $K$ — количество записей о дефектах.
4. **Вспомогательная функция: `get_mock_data()`**
   - Формирует эталонный набор тестовых данных предметной области для запуска и сопоставления с Java-реализацией.
